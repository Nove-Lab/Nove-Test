# v0.1.2 — Windows support, human-readable output, and the `licenses` verb

Released: 2026-06-22

This release closes out the post-MVP polish backlog and graduates
Windows to a Tier-1 supported install target.

## Highlights

- **Windows native install**. `irm https://raw.githubusercontent.com/Nove-Lab/Nove-Test/main/scripts/install.ps1 | iex`
  now fetches a signed `.exe`, verifies its SHA-256, and installs to
  `%USERPROFILE%\.local\bin\novetest.exe`. The CI matrix builds the
  Windows binary on every push; the install one-liner stops 404'ing
  the moment this release tag lands.

- **Human-readable text output by default**. Running `novetest <verb>`
  on a TTY now prints a tidy summary line — `✓ 42/42 passed in 3.1s`,
  grouped `licenses` listings, etc. — instead of the pretty-printed
  JSON it used to emit. AI agents continue to pin
  `--output json` (or `NOVETEST_OUTPUT=json`) for the byte-frozen
  `novetest/v1` contract; nothing breaks for programmatic consumers.

- **New `novetest licenses` verb**. Enumerates the 5 third-party
  components Nove Test redistributes or links to (cyclopts, numpy,
  JUnit Platform Console, PyApp, python-build-standalone) as a
  structured envelope. `--full` additionally inlines the verbatim
  ~15 KB NOTICES.md body — Apache 2.0, BSD 3-Clause, EPL-2.0 texts
  reproduced byte-identical to their upstream canonical sources. AI
  agents and license-audit tools no longer need to unzip the wheel or
  scan `*.dist-info/licenses/` to discharge Apache 2.0 §4(d).

- **First-run latency budget, gated in CI**. Every release-test run
  measures cold-start `novetest --version` and fails the build above
  25 s. Empirical current measurement: 10.5 s on Ubuntu (well within
  the documented 5–15 s budget).

## Internal polish (no user-visible API change)

- **Wheel attribution surface CI-probed**. The release build fails if
  `NOTICES.md` ever stops shipping inside the wheel under
  `*.dist-info/licenses/`. Regression guard for the PEP 639
  auto-discovery path.

- **Verbatim license texts inlined into `NOTICES.md`**. Apache 2.0
  and BSD 3-Clause full canonical bodies live alongside the per-package
  attribution blocks. The wheel's attribution document is now the
  single authoritative surface — no `*.dist-info/` scan required.

- **`workspace_relpath` utility promotion**. Coverage-private path
  helpers lifted to `src/novetest/utils/path_utils.py` and shared with
  Localization. Same cross-platform behavior (Windows cross-drive
  fallback included), just shared across the engine territories.

- **v1 metadata bridge sunset**. The `coverage_unavailable_kind` /
  `_message` keys formerly emitted on `RunRecord.metadata` by the
  dotnet adapter are fully retired. `envelope.warnings[]` is now the
  single canonical user-visible surface for adapter warnings. The
  one-release backward-compat window expired cleanly between v0.1.1
  and v0.1.2.

## Version-string mechanics

This release is the second consecutive 1-line `pyproject.toml::version`
bump under the Path A pattern established in v0.1.1. The runtime
envelope's `data.installedVersion`, the wheel METADATA `Version:`,
`uv pip show novetest`, and `novetest.__version__` all read
`importlib.metadata.version("novetest")` and report `0.1.2` in
lockstep. Zero string duplication anywhere in `src/`.

## Tier-1 platforms

| Platform | Install method | Binary |
|---|---|---|
| Linux x86_64 | `curl -fsSL .../install.sh \| sh` | `novetest-linux-x86_64` |
| Linux aarch64 | `curl -fsSL .../install.sh \| sh` | `novetest-linux-aarch64` |
| macOS universal2 | `curl -fsSL .../install.sh \| sh` | `novetest-macos-universal2` |
| Windows x86_64 | `irm .../install.ps1 \| iex` | `novetest-windows-x86_64.exe` |

All four binaries are PyApp wrappers around python-build-standalone
CPython 3.11; first invocation bootstraps the interpreter on demand.

## Upgrading from v0.1.1

Re-run the install one-liner for your platform — it overwrites the
binary in place. No on-disk Project Store (`.novetest/`) migration is
required; the JSON envelope schema is unchanged (`novetest/v1`).

## Known follow-ups (not blocking v0.1.2)

- `novetest --help --output json` top-level command-surface listing
  does not yet enumerate `licenses` (a tiny follow-up cycle will add
  the entry and regen the protected help-envelope snapshot). The verb
  is fully discoverable via `novetest licenses --help`.
- `OutputMode.TEXT` does not yet render ANSI color or tables — the
  current text mode is a clean monochrome summary. Color/table polish
  is a future polish cycle.
