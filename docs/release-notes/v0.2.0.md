# v0.2.0 — the refactoring-program behavior deltas

Released: 2026-07-22

This is a **behavior-carrying** release. Unlike v0.1.3 (a source-unchanged
tag), v0.2.0 tags `main` after the 2026-07-05 → 2026-07-22 refactoring program
(49 merged slices across four waves). The JSON envelope schema is **still
`novetest/v1`** — the wire *shape* did not change. What changed is **exit-code
classification, the side-effects of read-only verbs, the advertised command
surface, pytest interpreter selection, envelope path formatting, and
recommendation-synthesis accuracy**. Every wire-visible delta in the first
section below was ratified deliberately at its review gate; if you scripted
against v0.1.3 behavior, read that section before upgrading.

## ⚠ Breaking-adjacent behavior changes (read before upgrading)

The JSON envelope schema is unchanged (`novetest/v1`); what moved is *exit
codes, read-verb side effects, the command surface, interpreter selection, and
path spelling*, not the envelope shape. AI agents should keep matching the
stable string `code` in `errors[0]` rather than the numeric exit code.

### 1. Exit / error-code reclassifications

| `errors[0].code` | Exit before | Exit now | When |
|---|---|---|---|
| `adapter-invalid-target` | 4 | **2** | a dash-/flag-/shell-metachar-shaped test target is rejected pre-spawn (usage error, not an engine problem) |
| store-corruption (`store-corrupt` class) | inconsistent | **5** | an addressed-but-corrupt Project Store is read; now propagated consistently, extended to `inspect` |

- **`adapter-invalid-target` moves from exit 4 to exit 2.** A malformed
  caller-supplied target is a *usage error* → exit 2; exit 4 wrongly steered an
  agent toward install/readiness remediation that cannot fix a bad argument.
  The wire error-code **string** `adapter-invalid-target` and the envelope
  **shape** are unchanged — only the exit **int** moves. Every other
  `AdapterInvocationError` kind
  (`missing-engine`/`missing-plugin`/`missing-binary`/`unparseable-output`/`timed-out`)
  **stays exit 4**.
- **Store-corruption now escalates to exit 5 consistently.** A Project Store
  that exists but is corrupt surfaces exit 5 on the verbs that read it,
  including `inspect`. This is the "addressed-but-corrupt" class — distinct from
  `uninitialized` (exit 2, no store on the upward walk).

### 2. Read-only verbs no longer create or write store state

Workspace resolution (walk **up** to the nearest `.novetest/`) is now **pure
resolution**. The one-time pre-v0.1.3 pin **backfill**, and the
`engine-ambiguous` refusal, moved entirely onto the **execution** path — they
are reached only by `run` and `test`.

- **Read verbs never write.** On a legacy pre-pin store (created before the
  anchored-pin model) a read-only verb no longer backfills the engine pin as a
  side effect. The pin is backfilled the first time you run an **execution**
  verb (`run` / `test`) there.
- **Read verbs on an ambiguous legacy store now proceed instead of refusing.**
  Where a legacy, pin-less, engine-ambiguous store previously made a read-only
  verb exit `engine-ambiguous` (exit 2), the read verb now **proceeds
  engine-less and exits 0, writing nothing**. Execution verbs on the same store
  still refuse with `engine-ambiguous` (exit 2) until you re-pin with
  `novetest init --engine <name>`.
- **Net effect:** the read-verb "seam" (points at which a read could mutate or
  refuse on a legacy store) went from 2 to 0. Scripts that inspect a legacy
  store are now guaranteed side-effect-free.

### 3. New advertised surface: `novetest localization latest`

`novetest localization latest` — "ranked suspicious code locations for the
latest analyzable run" — is now advertised in `--help` and in the onboarding
command surface (`novetest --help --output json`). It was reachable before but
undocumented; this is an **additive** surface change (no verb removed or
renamed).

The read-verb surface for the derived engines, stated precisely (there is **no**
`show` shorthand for either):

| Engine | Read verbs |
|---|---|
| regression | `novetest regression compare <a> <b>`, `novetest regression latest` |
| localization | `novetest localization <run_id>`, `novetest localization latest` |

### 4. Venv-first pytest interpreter selection

The pytest adapter now prefers the **SuT's own virtualenv** interpreter. When
the target workspace ships a `.venv` whose pytest console script is present
(`.venv/bin/pytest` on POSIX, `.venv\Scripts\pytest.exe` on Windows), the child
runs on that venv's Python via `<python> -m pytest`; otherwise it falls back to
the interpreter running novetest. It never execs a bare `pytest` off `PATH`.

- **Why it matters:** the shipped single-file binary bundles its own CPython. A
  project whose pytest lives only in a project `.venv` used to be invisible to
  that bundled interpreter; venv-first resolution fixes that. If your project
  runs pytest from a `.venv`, novetest now uses it automatically.
- The child environment is also pinned deterministic (`PYTHONHASHSEED=0`,
  `CI=1`, `FORCE_COLOR=0`) and an inherited `PYTHONPATH` is dropped so a
  host-profile tree cannot shadow the SuT's dependencies.

### 5. POSIX-normalized envelope paths

Artifact paths inside `record.json` and the run/test envelopes are now emitted
with **forward-slash (POSIX) separators on every host**. On POSIX this is a
no-op (identity); on Windows, envelope paths that previously carried `\`
separators now carry `/`. Cross-host consumers (e.g. an agent comparing
envelopes produced on Linux CI and a Windows workstation) get stable, identical
path strings.

- Relatedly, a target expression's regression-baseline key is now **lexical**:
  on-disk existence and cosmetic spelling (`a/../b` vs `b`) no longer fracture a
  target's baseline series, so the same logical ask from different directories
  lands in the same series.

### 6. Recommendation-synthesis accuracy

Two synthesis fixes change **which** recommendations surface and the resolvability
of one citation selector. The `recommendation_schema_version` is unchanged (slot
keys are identical); the change lives in which recommendations appear and in the
`evidence_citations` payload.

- **Compound swallow-key narrowed to `(file, primary_line)`.** When a
  regression+localization *compound* recommendation is emitted, the
  constituent `investigate_location` recommendations it absorbs are now keyed on
  the precise `(file, primary_line)` pair instead of bare file membership.
  **Consequence:** a same-file but *different-symbol / different-line*
  `investigate_location` in a file where some *other* symbol fired a compound is
  **no longer silently dropped** — it surfaces as its own recommendation.
  Genuine constituents (same code location) are still absorbed.
- **`coverage_gap` citations now round-trip.** A `coverage_gap` recommendation's
  `localization_finding` citation carries a resolvable
  `{rank, file, primary_line, related_finding_id}` selector (previously it
  emitted `rank`/`primary_line` as `null` and dropped `related_finding_id`).
  The `related_finding_id` is a positional `entry_index_<i>` handle resolved as
  `entries[i]` (0-based) of `novetest localization <run_id>`, distinct from the
  1-based `rank`; the citation now resolves both by that handle and by
  `(file, primary_line)`.

## Correctness fixes now shipping (resolves v0.1.3 known follow-ups)

v0.1.3 was a source-unchanged anchor and explicitly deferred a set of native-engine
correctness items. v0.2.0 ships them:

- **Cobertura multi-`<class>` merge** — same-file entries split across multiple
  `<class>` elements are merged per document (was a v0.1.3 known follow-up).
- **Per-run JUnit report isolation** — a stale JUnit report can no longer bleed
  into a later run (was a v0.1.3 known follow-up).
- **Go sub-package scoping** — `go`-target conversion handles sub-package and
  `./...` scopes correctly.
- **Zero-collection visibility** — a run that normalizes to `passed` with an
  empty result set now emits a `zero-tests-collected` warning in the envelope
  (visibility only; exit code and schema unchanged), so an agent can no longer
  read "all tests pass" over a suite that never collected anything.
- **SBFL / localization correctness** — dstar2 denominator-zero handling,
  outcome-exclusion single-sourcing, and `failure_proximity` support for the
  junit/xunit engines.

## Robustness & operational hardening

User-visible reliability work landed across the program:

- **Atomic store writes** — `store.json` and tombstone mutations are written
  mutate-then-single-`rename`, so a crash mid-write cannot leave a truncated or
  half-updated store.
- **Subprocess lifecycle hardening** — process-tree kill, bounded pipe drain,
  and a capture cap on adapter child processes; shell-metachar injection
  defense on the Windows launcher.
- **Registration-surface guarantee** — a completeness test walks the live
  command tree and asserts three-way agreement between the Cyclopts app, the
  renderer table, and the onboarding command surface, so an advertised verb can
  never silently drift from what actually runs.

## Version-string mechanics

This release bumps `pyproject.toml::version` (`0.1.3 → 0.2.0`) and re-locks
`uv.lock` (the `novetest` self-pin `0.1.3 → 0.2.0` — a one-line lockfile
delta). There is **no version-string duplication in `src/`**: the runtime
envelope's `data.installedVersion`, the wheel METADATA `Version:`,
`uv pip show novetest`, and `novetest.__version__` all read
`importlib.metadata.version("novetest")` and report `0.2.0` in lockstep.

## Tier-1 platforms

| Platform | Install method | Binary |
|---|---|---|
| Linux x86_64 | `curl -fsSL .../install.sh \| sh` | `novetest-linux-x86_64` |
| Linux aarch64 | `curl -fsSL .../install.sh \| sh` | `novetest-linux-aarch64` |
| macOS universal2 | `curl -fsSL .../install.sh \| sh` | `novetest-macos-universal2` |
| Windows x86_64 | `irm .../install.ps1 \| iex` | `novetest-windows-x86_64.exe` |

All four binaries are PyApp wrappers around python-build-standalone CPython
3.11; the first invocation bootstraps the interpreter on demand. Every binary
ships a `.sha256` sidecar, and the install scripts verify the checksum before
placing the binary. `windows-arm64` remains unsupported pending
python-build-standalone availability.

## Upgrading from v0.1.3

Re-run the install one-liner for your platform — it overwrites the binary in
place. The on-disk Project Store (`.novetest/`) needs **no manual migration**:
the JSON envelope schema is unchanged (`novetest/v1`), and a pre-anchored-pin
store still backfills its engine pin automatically — now on the first
**execution** verb (see breaking-adjacent item 2), not on a read verb. The
things to re-check are:

- Any script that keyed on `adapter-invalid-target` returning **exit 4** — it is
  now **exit 2** (the string code is unchanged; pin to the string).
- Any script that relied on a read-only verb backfilling the pin or refusing on
  a legacy ambiguous store — read verbs are now side-effect-free and proceed.
- Any consumer that parsed Windows envelope paths with `\` separators — they are
  now `/` (POSIX) on every host.
