# v0.1.3 — the anchored-pin model, `reset`, and `test --reruns`

Released: 2026-07-07

This is a **behavior-carrying but source-unchanged** release: v0.1.3 tags
the current `main` exactly as it stands, with **no new code**. It is
functionally **v0.1.2 plus everything that merged since** — chiefly the
**anchored-pin engine-selection model**, the `novetest reset` verb, and the
`novetest test --reruns N` flag. No bug fixes are introduced in this cut; the
known correctness follow-ups tracked for the next development wave ship **as
they already are on `main`** (they all also exist in v0.1.2 — no behavior
regresses relative to v0.1.2). v0.1.3 exists to fix a **verified, taggable
point** as the rollback anchor before the next round of changes lands.

## ⚠ Breaking-adjacent behavior changes (read before upgrading)

These are not source changes introduced by v0.1.3 — they are the
already-merged **anchored-pin model** becoming the first *tagged* behavior
after v0.1.2. If you scripted against pre-anchored-pin behavior, review the
four items below. The JSON envelope schema is still `novetest/v1`; what
changed is *engine selection, workspace resolution, and the error-code
surface*, not the wire shape.

### 1. `novetest init` now anchors (pins) an engine

`init` records **which** engine you consented to, at **which** directory, in
`store.json`. Selection is no longer guessed at run time.

| Situation at the `init` directory | Behavior |
|---|---|
| Exactly one ecosystem marker | Creates `.novetest/` and records the engine **pin**. Onboarding is unchanged — zero new flags for the common case. |
| **No** marker | Creates **nothing**. Exits `no-engine-detected` (exit 4) and reports bounded sub-project candidates in `data` so you can `cd` in and `init` there. |
| **Two or more** markers | Creates **nothing**. Exits `engine-ambiguous` (exit 2); pick explicitly with `novetest init --engine <name>`. |

- `--engine <name>` is optional (required only when ambiguous; accepted
  always — explicit wins over detection). An out-of-matrix value fails as
  `invalid-flag` (exit 2).
- Re-running `init --engine <other>` at an initialized location **re-pins in
  place** — same store, run history retained; a second `.novetest/` is never
  created.
- **What changed:** previously an ambiguous or markerless directory could
  silently pick an engine by fixed priority (or create a store you did not
  intend). v0.1.3 refuses loudly instead of guessing — an agent can no longer
  believe "all tests pass" while an entire suite silently never ran.

### 2. Every verb resolves its workspace by walking **up** to the nearest `.novetest/`

Workspace resolution is now git-style: each verb walks **upward** from your
current directory to the nearest `.novetest/` (**nearest wins**), and executes
the engine pinned there with its native scope. No verb ever scans downward,
and no verb ever guesses an engine.

- Running a verb from any subdirectory of an initialized workspace now works —
  it resolves to the workspace anchor, not to the current directory.
- A **bare** invocation (no target argument) is **workspace-scoped**
  (`target_expression = ""`) **regardless of which subdirectory you ran it
  from** — the current directory never silently narrows scope. Subsets require
  an **explicit target**, and explicit target paths are normalized **relative
  to the anchor**, so the same ask from different directories lands in the same
  baseline series.
- Running a verb where no `.novetest/` exists on the upward walk errors
  immediately as `uninitialized` (exit 2), with no downward filesystem scan.
- **Stores created before v0.1.3** have no pin field. On their first verb the
  pin is **backfilled silently** if the anchor has one unambiguous engine; an
  ambiguous anchor errors `engine-ambiguous` and asks you to re-pin with
  `novetest init --engine <name>`. One-time cost, no store rebuild.

### 3. New and changed exit / error codes (agents: pin to the string codes)

| `errors[0].code` | Exit | When |
|---|---|---|
| `no-engine-detected` | **4** | `init` at a markerless directory; `data` carries discovered sub-project candidates |
| `engine-ambiguous` | **2** | `init` (or first-verb migration) sees ≥2 ready engine candidates and no explicit `--engine` |
| `uninitialized` | **2** | a verb ran with no `.novetest/` on the upward walk |
| `invalid-flag` | **2** | `--engine` outside the six-engine matrix, or a negative `--reruns` |
| `confirm-required` | **2** | `novetest reset` run without `--confirm` |

`no-engine-detected` and `engine-ambiguous` are **new** strings introduced by
the anchored-pin model. AI agents should match the stable string `code` in the
JSON envelope rather than the numeric exit code.

### 4. New surfaces: the `reset` verb and `test --reruns N`

- **`novetest reset --confirm`** wipes the active Project Store and re-runs
  `init` at the store's anchor in one atomic operation. `--confirm` is
  **mandatory** — omitting it exits `confirm-required` (exit 2). This replaces
  the old `rm -rf .novetest && novetest init` guidance. The happy-path
  envelope reports `data.items_removed` (per-category counts) and re-pins the
  previous engine across the wipe.
- **`novetest test --reruns N`** (default `N = 0` = today's behavior, no
  replay). With `N > 0`, after the run is recorded novetest replays failed
  tests and can surface `flaky_suspected` recommendations. The envelope shape
  is unchanged; `data.stage_eligibility.replay` moves from `"not_run"` to
  `"available"`, and per-test replay evidence is persisted under
  `.novetest/replay/results/`. Exit-code matrix is unchanged (0 / 3 by run
  status; replay outcomes do not change it). A negative value is rejected as
  `invalid-flag` (exit 2).

## Version-string mechanics

This release is a single-line `pyproject.toml::version` bump
(`0.1.2 → 0.1.3`) under the established Path A pattern — **no `uv.lock`
regeneration, no `src/` change**. The runtime envelope's
`data.installedVersion`, the wheel METADATA `Version:`, `uv pip show
novetest`, and `novetest.__version__` all read
`importlib.metadata.version("novetest")` and report `0.1.3` in lockstep. Zero
version-string duplication anywhere in `src/`.

## Tier-1 platforms

| Platform | Install method | Binary |
|---|---|---|
| Linux x86_64 | `curl -fsSL .../install.sh \| sh` | `novetest-linux-x86_64` |
| Linux aarch64 | `curl -fsSL .../install.sh \| sh` | `novetest-linux-aarch64` |
| macOS universal2 | `curl -fsSL .../install.sh \| sh` | `novetest-macos-universal2` |
| Windows x86_64 | `irm .../install.ps1 \| iex` | `novetest-windows-x86_64.exe` |

All four binaries are PyApp wrappers around python-build-standalone CPython
3.11; the first invocation bootstraps the interpreter on demand. Every binary
ships a `.sha256` sidecar, and the install scripts verify the checksum before
placing the binary. `windows-arm64` remains unsupported pending
python-build-standalone availability.

## Upgrading from v0.1.2

Re-run the install one-liner for your platform — it overwrites the binary in
place. The on-disk Project Store (`.novetest/`) needs **no manual migration**:
the JSON envelope schema is unchanged (`novetest/v1`), and a pre-v0.1.3 store
backfills its engine pin automatically on the first verb (see breaking-adjacent
item 2). The only thing to re-check is any script that relied on the
pre-anchored-pin selection or error-code behavior described above.

## Known follow-ups (ship as-is in v0.1.3; not fixed in this cut)

v0.1.3 is a source-unchanged tag, so the correctness work queued for the next
development wave is **not** included here. These conditions are present in
v0.1.2 as well — v0.1.3 does not worsen any of them; it simply fixes a
rollback anchor before they are addressed:

- Zero-collected explicit targets can still report `status: "passed"` on
  engines that produce a run record with no results (a caution documented in
  the troubleshooting docs).
- The remaining native-engine correctness and hardening items tracked for the
  next wave (e.g. go sub-package scoping, stale JUnit report isolation,
  Cobertura multi-class merge) land in later releases, not in this cut.
