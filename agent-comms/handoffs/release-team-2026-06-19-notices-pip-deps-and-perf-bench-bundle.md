#### Apache 2.0 leading-blank off-by-one (DoD #1 nuance)

The DoD command as written —

```
diff <(curl -fsSL https://www.apache.org/licenses/LICENSE-2.0.txt) \
     <(awk '/Apache License/,/limitations under the License./' NOTICES.md)
```

— **cannot return strictly empty by construction**, regardless of how the
verbatim text is embedded in NOTICES.md. The canonical Apache file is 202
lines, of which the first is blank; lines 2–202 are the title + verbatim
license body. The awk pattern `/Apache License/` matches the FIRST line
containing that literal; awk-range captures from THAT line onward. The
canonical file's leading blank line precedes the first awk match, so the
awk-extracted range is structurally lines 2–202 (= 201 lines). The diff
against the full 202-line curl output thus shows:

```
1d0
<
```

— a single leading blank line absent on the RHS. The substantive verbatim
text matches byte-for-byte, validated via:

```
diff <(tail -n +2 /tmp/apache-2.0.txt) \
     <(awk '/Apache License/,/limitations under the License./' NOTICES.md)
```

→ empty output, exit 0. PM may either (a) accept this nuance and amend the
DoD #1 wording at cycle close to use the `tail -n +2`-stripped LHS, or
(b) leave as-is given the substantive intent is met. Surfaced here rather
than as a question file because no policy decision is needed — the verbatim
license text IS byte-identical to the canonical upstream.
