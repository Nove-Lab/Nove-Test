## Load-bearing learnings (4)

### 1. Path A 4-way concordance stabilized — release cycles are now mechanical

v0.1.1 was the proof-of-concept for the `importlib.metadata.version("novetest")` pattern (decision 2026-06-10). v0.1.2 is the **stabilization release** that proves the 1-line edit produces 4-way concordance reliably:

- Wheel METADATA `Version:` (hatchling reads pyproject at build time)
- `uv pip show novetest` (uv reads installed wheel METADATA)
- Runtime envelope `data.installedVersion` (`novetest.__version__` → `importlib.metadata.version` → dist-info METADATA at import time)
- `novetest.__version__` (Python attribute aliasing the metadata lookup)

**Pattern adopted as steady-state**: every future release cycle is a single `pyproject.toml::version` edit + auto-resynced `uv.lock` self-reference + handoff. ~30 minutes wall time end-to-end on a clean dev host (mostly spent waiting on `uv build`). The 2-file commit (`pyproject.toml` + `uv.lock`) is the binding minimum; brief authors should pin this as the surgical scope.

### 2. Parallel-cycle WORKLOG conflict resolution convention pinned

When two parallel cycles add same-day `WORKLOG.md` entries on top of the file, the rebase produces a deterministic conflict because both teams prepended a `## 2026-06-22 ...` block.

**Resolution adopted (now binding)**: the cycle whose handoff was filed **LATER** goes on TOP of the file (matches the "newest-on-top" doc-level convention; handoff timestamps serve as the tie-breaker). The earlier-filed cycle sits below the divider.

This cycle: Release handoff filed 10:20; Orchestration handoff filed 10:13 → Release entry on top, Orchestration below. Both entries preserved byte-equivalent; the divider stays single `---` line.

**Pattern reusable** for any future parallel-cycle pair where same-day WORKLOG entries collide.

### 3. `gh` auth read-only state is auth-identity-scoped, not a permanent project condition

The 2026-06-18 Windows install cycle pinned `gh` auth as `READ`-only for the `yongjunshin` HTTPS identity, requiring CEO push for all branch/tag operations. That cycle's history (`2026-06-18-windows-install-ps1-and-binary-pipeline.md` learning #3) framed it as "the new procedural reality."

This cycle's Release team session pushed successfully via the `github.com-nove` SSH host alias (a distinct identity with write access). The 2026-06-18 constraint was therefore **auth-identity-scoped**, not a permanent state.

**Refined pattern** for future Release cycles:
1. At session start, dry-run a push (`git push --dry-run`) or check `git remote -v` + the SSH host resolution. If push works, brief's "CEO push" procedure is OPTIONAL fallback.
2. If push 403's, CEO push is REQUIRED as in 2026-06-18 cycle.
3. Both paths are valid; each session re-verifies its own auth state.

**Implication for PM brief authoring**: do not assume push capability either way. Document both procedural paths; let the Release team pick the live one and amend the handoff accordingly. This cycle's handoff demonstrates the amendment pattern (post-push-success amendment in commit `5519ccf`).

### 4. PYTHONPATH pollution is a dev-host pattern to watch for

This cycle's Release team session inherited a ROS2-flavored `PYTHONPATH` pointing at Python 3.10 site-packages, causing `uv run novetest` to crash with `ModuleNotFoundError: No module named 'numpy._core._multiarray_umath'`. All verification commands required `unset PYTHONPATH &&` prefix to clean the env.

**This is dev-host-specific** (GitHub Actions runners have no such pollution; CI is immune). But it affects future local verification on the same dev host.

**Recommended pattern** for future Release / Orchestration cycles on this dev host: prepend `unset PYTHONPATH &&` to every `uv run`, OR launch a fresh subshell with the env cleared. Pinned in handoffs going forward.
