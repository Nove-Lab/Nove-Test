### Step 5 (Multi-module Maven — coverage_xml dichotomy)

This step covers the **open item #2** from the handoff that Manual Test should probe: single-module emits `coverage_xml` as a **file** path; multi-module emits it as a **directory** path. The fixture set ships only single-module variants; multi-module is verified by code inspection on this slice. Manual Test may skip this step if no multi-module fixture is at hand; the dichotomy is documented for future cross-engine consumers.

Pinned from source:

| Project shape | `metadata["multi_module"]` | `artifact_paths["coverage_xml"]` resolved value |
|---|---|---|
| Single-module Maven | `"false"` | `.../native/coverage/jacoco.xml` (FILE) |
| Multi-module Maven | `"true"` | `.../native/coverage` (DIRECTORY) — `_stage_coverage_xml(sub_path=<module>)` lands each per-module file at `coverage/<module>/jacoco.xml` |
| Single-module Gradle | `"false"` (multi-module Gradle not in scope this cycle) | `.../native/coverage/jacoco.xml` (FILE) |

Downstream consumers MUST consult `metadata["multi_module"]` before opening `artifact_paths["coverage_xml"]` as a file vs walking it as a directory. The Coverage engine's `_derive_junit_jacoco` already handles this; manual probes that read `coverage_xml` directly should branch on `multi_module`.

## Critical edge cases worth probing

1. **`reports_dir` retry idempotency.** `_stage_reports_dir` uses `shutil.copytree(..., dirs_exist_ok=True)` so a second `novetest run` against the same workspace doesn't blow up on pre-existing dest. Manual probe: run `novetest run` twice in a row and confirm the second run also lands at `exit ∈ {0,1}` and produces a fresh `TEST-*.xml` inside `reports_dir`.

2. **`payload["warnings"]` carrying `missing-jacoco` shape.** When `--coverage` is requested but the fixture's `pom.xml`/`build.gradle.kts` does NOT declare jacoco, the hotfix emits a structured warning instead of populating `coverage_xml`. Pinned shape:
   ```json
   {"kind": "missing-jacoco", "message": "coverage was requested but ..."}
   ```
   Probe by temporarily removing the jacoco-maven-plugin block from the fixture's pom.xml and re-running with `--coverage`. The envelope's `data.memory_entry.run_record.metadata` does NOT carry the warning; the warning lives on the adapter's `payload["warnings"]` which is internal — surface check is `coverage_outcome.kind == "unavailable"` with `reason` non-empty.

3. **Maven multi-module reports staging preserves module folder.** Per D2, multi-module workspaces emit one CoverageFactSet but each module's `TEST-*.xml` and `jacoco.xml` land under `reports/<module>/` and `coverage/<module>/jacoco.xml` respectively. If Manual Test has time to scaffold a multi-module Maven fixture (two modules, one calculator each), confirm both `TEST-*.xml` sets stage independently.

4. **JDK 11 vs JDK 17 floor.** The hotfix dev host runs JDK 11 (`11.0.31`); the supported-engine matrix floors at JDK 17. The hotfix did NOT amend the readiness probe to hard-reject < 17 (open item #3 in the handoff). On JDK 11 the vendored Console Launcher 1.11.4 still functions for the smoke. Manual Test should equip JDK 17 (per `scripts/dev-host-setup.md §5`) and confirm `engine_readiness.engine_version` or equivalent surfaces ≥ 17.

5. **Gradle's signed parametrized display name.** JUnit 5 parametrized tests with the `(int)[1]` etc. suffix MUST pass through `_strip_trailing_parens` untouched. Probe: write a small parametrized test in the gradle fixture (e.g. `@ParameterizedTest @ValueSource(ints = {1,2,3}) void testFoo(int arg)`) and confirm the resulting `identity` retains the parametrized signature.

6. **Defect-1 regression canary.** If `artifact_paths["reports_dir"]` EVER resolves to a path that fails `is_relative_to(store.path)`, the orchestration layer raises `ValueError` and the envelope flips to `cli-error` (exit 2). Step 0's `returncode in (0, 1)` assertion is the canary; any future Run-team patch that re-introduces the violation lights it up immediately. Manual Test does not need to construct this case; it's automated by the CLI smoke.
